# Backend for marketing module

## 1. Prerequisitesdsd
* **NodeJS:** 14+
* **IDE:** VSCode, Webstorm
* **Build environment:** Linux, MacOS (Windows is not supported)
***
## 2. Run service locally
To run a service, go to root project:
```shell
cd <path-to-project>
```
then run command:
```shell
./scripts/run_service.sh <service-name>
```

To build a service, run command:
```shell
./scripts/build_service.sh dev <service-name>
```
After building, there are 2 zip files under `temp` folder:
* `function_<service-name>.zip`
* `layer_<service-name>.zip`

Upload these files to lambda function and layer to test the service in cloud.
***
## 3. Make new service
Install `tobackend` CLI:
```shell
npm install -g tobackend-cli
```

Then make new service:
```shell
tobackend service --model <model-name> <service-name>
```

For example:
```shell
tobackend service --model User user-service
```

After running this command, new service folder should be under `/src/modules`.

Also, `tobackend` CLI supports a lot of command. For more information, see here: https://www.npmjs.com/package/tobackend-cli
***

## 4. Service structure
A service is responsible for single functionality and independant with others, bases on microservice idea. For instance, `user-service` should only includes entities/methods related to manage/create/update/... users.

By generating template using `tobackend` CLI, a service should follow clean architecture and its structure look like:
* `models` includes declarations of entities such as User, Tour,...
* `providers` includes classes which is used to interactive with platform APIs, database,...
* `repositories` represents adapter layer, includes methods for transform data between domain layers and providers. In this layer, data retrieved from the database should be converted to the format which is most convenient for the use cases and entities layer.
* `useCases` includes use cases, in there an use case should handle flow of data to perform a function. For example: the createUser use case should take the email address and password from request, register a new user with these paramters then provide resources for this user.
* `utils` includes a lot of utility methods which is used in service.
* `app.local.ts` the file required to run locally.
* `lambda.ts` the file required to run on AWS Lambda Function. This file, if it is generated by the CLI, has `init` function. You can modify it to do something such as connect the database or load configuration.
* `app.ts` the main controller, where routes are mapped to handler functions.

__**NOTE**: Be aware that all route handlers must validate request parameters.__
